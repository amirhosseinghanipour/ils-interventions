# Deadline-constrained donor interventions

This pilot uses SmolLM2-1.7B-Instruct on route reversal and Qwen2.5-0.5B-Instruct on gift assignment. Each cell has 24 held-out prompt/donor pairs across six held-out templates. Tokens and donors come from the existing panel-scaling split. No prompt was selected by its measured test interaction strength. A fixed random round-robin panel takes 32 or 64 heads from layers 11, 14, 17, 20 and 23. The smaller panel is nested in the larger one. Gate 1 replaces the current recipient head output at every position with the corresponding clean donor head activation. Gate 0 retains the current recipient activation. The score is the change in donor-minus-original answer logit margin relative to the unmodified recipient.

Run from the repository root in a CUDA PyTorch and Transformers environment. Install the benchmark dependencies with `pip install -e '.[anytime]'`. Limit BLAS and OpenMP to one thread for comparable CPU fitting times. Supply local Hugging Face checkpoint directories.

```sh
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false
python -m scripts.anytime.benchmark profile /path/to/SmolLM2-1.7B-Instruct route artifacts/anytime/large
python -m scripts.anytime.benchmark profile /path/to/Qwen2.5-0.5B-Instruct gift artifacts/anytime/qwen
python -m scripts.anytime.benchmark search /path/to/SmolLM2-1.7B-Instruct route artifacts/anytime/large
python -m scripts.anytime.benchmark search /path/to/Qwen2.5-0.5B-Instruct gift artifacts/anytime/qwen
python -m scripts.anytime.score artifacts/anytime
```

The profiler times exact batches of 1 to 512 masks, and 1, 2, 4 or 8 simultaneous Rademacher directions. B_eq multiplies median steady-state exact masks/ms at the fastest tested batch size by FD-HVP batch time divided by the number of directions. This is a throughput exchange rate. Small deadline-limited forward jobs can achieve a lower rate. For one-sided products, the midpoint gradient is already available. The search uses central differences with step 0.125. The step sweep compares both estimators to the central estimate at 0.0625. This comparator itself has FP16 rounding error. Kernel names come from actual profiled dispatch. Weights and activations are FP16; interpolation, gate gradients and the two-token readout use FP32. Native audits compare a batched full decoder with Boolean replacements against prefix replay. Canonical pool labels are rescored in a common batch configuration so the same returned ID gives every method the same score.

Each prompt has 512 search candidates (including no-op and full patch) and 512 disjoint, evaluation-only masks. Both sets use complement pairs. The exact incumbent starts as the defined zero-effect no-op. Each timed run builds fresh prompt caches. Model load, package imports, offline oracle measurements and scoring held-out predictions are outside the online deadline. The same candidate pool and its complement indices are supplied to all methods. All prompt-specific tokenization, model caches, derivatives, fits, candidate scoring, acquisition, exact verification, and return to the consumer are timed. The consumer timestamps every delivered update and holds the latest incumbent while the worker is busy. A final synchronous call can finish after the deadline. Its late updates receive zero credit. Thus the guarantee applies to the streamed incumbent; the trace also saves total blocking call duration. A development-timed verification allowance is kept before admitting training stages. GPU runtime variability can exceed this allowance.

All gradient-based arms start with a midpoint proposal verified in the first slot. Midpoint continues verifying candidates by its fixed ranking. HVP and zero-HVP complement estimators share the same fitting and acquisition policy. Independent uniform pairs seed the fit; later batches are half uniform and half high-predicted-effect pairs. The fit uses separate even and odd channels, a bounded, unpenalized scale on the estimated cross-Hessian, and continuous ridge for residuals. Dense ridge uses the previous panel benchmark's normalized columns and fixed penalty. The zeroth-order tree comparator skips the gradient and fits LightGBM on raw masks, converts trees to Fourier terms, and uses energy truncation and ridge refinement following ProxySPEX. Its shallow fixed hyperparameters and shared calibration mask distribution are study adaptations. Raw cached exact spends the available time on forward batches. Fixed-pool regret uses the largest effect measured in the full evaluation-only search pool. We make no global optimum claim over all Boolean subsets.

For the local-to-Boolean diagnostic, 24 random head pairs per prompt each receive eight independently sampled Boolean backgrounds. The four-mask mixed difference averaged across backgrounds estimates four times the degree-two Walsh coefficient. The diagnostic compares these estimates with single-column central differences and with the eight-direction sketch. Correlations are centered within prompt. Split-half correlation measures the noise of the Boolean reference. The stage-B gate uses four random complement pairs. Its two thresholds compare the empirical midpoint error and the projected quadratic RMS with a fixed target. False abstention counts are an offline diagnostic, conditional on the 512-mask midpoint MAE exceeding the target. The first eight labels and the HVP diagnostics are paid only when used online. No coverage guarantee is inferred from four pairs.

Each prompt file includes pool truth, held-out truth, signal diagnostics, and timestamps, incumbent IDs, paid effects, standardized effects, cumulative exact-label counts, and held-out MAEs of delivered predictors. Mask IDs replay from the stored seed. Curves use all 24 prompts for decision quality. MAE is plotted only when all 24 have delivered a predictor. Intervals on matched differences resample the six template clusters and are descriptive at this sample size.

A separate delivery audit starts an independent CPU process with its own wall clock and streams lightweight verified updates over a pipe. The consumer reports its last on-time incumbent even while the GPU worker is in a blocking call. Run `python -m scripts.anytime.delivery CHECKPOINT TASK artifacts/anytime/MODEL` after profiling. The audit records observed timer release jitter separately from message receipt time.

The same supplemental command also measures a second cached-exact baseline on all test prompts. After observing that a throughput-sized first batch could miss the entire deadline, we limited this baseline's development-estimated batch latency to one sixth of the deadline and streamed every batch. The original throughput-oriented baseline is retained. Neither policy reads test-pool labels before it pays for them. Run the delivery command for both models before scoring.

For the compact-circuit challenge, run the search with `--compact` on SmolLM2 gifts and Qwen routes, using separate output directories. Copy each model and K's original profile into the corresponding output directory first. The challenge reuses those hardware budgets without tuning them to the new task. Each candidate patches exactly eight heads. Complement masks still provide calibration, but are ineligible as returned interventions. The no-op remains legal. Masks and seeds differ from the original pilot. The script first evaluates the frozen midpoint proposal on eight development prompts. It skips the held-out search when median development regret is below 0.02 logits. If the challenge qualifies, the target effect gain is 0.01 logits over exact-only complement sampling, with uncertainty resampled over the six held-out templates. The compact profile file describes the original timing task and the challenge rows record the actual task.
